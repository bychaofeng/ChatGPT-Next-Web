## 2. 原型与总方案的差距

| 方向 | v0.3 基线 | 后续要完成的内容 |
|---|---|---|
| 自动个性化 | 不填背景、多能力暂定观察、可解释调度 | 扩展专业主题和情境，检验误判纠正、提示条件与公平性 |
| 动态出题 | 16道演示题，固定蓝图内改写题面 | 有版本的审核内容包、更多题目家族、生成与评估分级准入 |
| 画像 | 依据有效记录重建暂定投影 | 细粒度范围、来源和暴露追踪、合格独立及保持证据 |
| 病例讨论 | 围绕当前模拟题教学 | 独立模拟病例入口；真实病例另行授权与风险设计 |
| 解析展示 | 文本、提示和讨论 | 经核对的二维资源，再验证3D是否解决真实理解问题 |
| 工程可靠性 | 本地快照、有限队列和回归测试 | 生命周期、恢复、迁移、可访问性和设备安全测试 |
| 模型质量 | 提示词及结构/引用检查，mock测试 | 真实返回一致性、合理替代答案、未知和拒评行为验证 |

## 3. 阶段A：手机上完成一轮训练

任务：安装受控调试包，打开即练；独立作答、提示后改答、讨论、结束、重开和下一题均能完成。无需背景调查，也不能只能适配一个测试者。

验收：原题和首次答案可恢复；提示后表现不覆盖首次；暂停、取消、断网、重复提交不制造错误成绩；切换档案不串数据；横竖屏、返回键和应用重启不会误发请求；API 26及支持版本的界面可正常使用。

产出：记录设备、系统、提交SHA、复现步骤和实际结果。未测的条件标为未测，不因编译成功勾选。

## 4. 阶段B：真实API与提示词联调

在使用者本机配置服务地址、模型和Key，先选一个服务商。密钥不发送到开发聊天，不提交仓库。真实请求的内容及费用由使用者知情配置。

验收用例包含：合理但不同措辞的答案、信息不足、用户质疑、编造引用、错ID、额外字段、空返回、截断、超时和旧请求晚到。分别检查生成、评价、教学、摘要，而不是只验证能收到回复。

记录实际用量、等待和失败情况。模型更换或提示词更新后使用同一组固定输入回归；JSON通过和模型间一致不等于专业正确。

产出：可复查的联调记录、失败样例及修复。原始内容最小化，日志不保存密钥或可识别患者资料。

## 5. 阶段C：内容准入与可靠的训练体验

先扩充有限专业范围，但规则面向任何新用户。每个内容包包含目标、固定事实、适用范围、资料出处、版本、可接受的不同路径和核查状态。

将动态练习与可用于较稳定评价的任务分开。未审核生成题不获得正式评估资格；同一家族不靠改名字增加覆盖；知识或评分逻辑改变需重新核查。

验收：首次起步能找到合理任务；弱项补练不过度重复；强项有探索机会；新主题不继承未验证结论；用户求助、太难/太简单和结束均有合理路径；内容不足时明确说明验证限制。

产出：审核内容包、争议处理流程、独立于日常练习的验证案例和小范围使用记录。学习效果需另行设计与验证，不把体验满意当作能力提升。

## 6. 阶段D：进一步扩展

按实际试用需求选择，而非同时开工：独立模拟病例讨论、二维图与结构编号、3D资源、语音、持久化迁移、备份恢复、云端账号与多设备。

真实病例功能必须先定义授权、最小化、去标识化、模型服务商发送范围、删除和风险转介机制。不得自动把患者资料变成其他用户的题库。

长期学习调度可以探索更细的知识追踪，但任何算法都需明确适用范围和校准证据，不以一个不可解释的总分替代观察记录。

## 7. 每次提交通用验收清单

- [ ] 当前任务及评分依据固定，用户看过哪些信息可追溯。
- [ ] 首次回答、改答、提示与即时巩固不互相冒充。
- [ ] 有效评价有实际引用，争议/撤回后的画像可重建。
- [ ] 无资料新用户和不同作答轨迹均能继续训练。
- [ ] 网络失败、过期响应和重复重试不丢答案、不重复计数。
- [ ] 学习档案隔离，密钥不入库、不进提示词和日志。
- [ ] 模型、提示词、内容、数据结构变动有版本和回归记录。
- [ ] 新功能标注已实现/未实现，测试注明mock、真实API或设备条件。
- [ ] 不把工程通过宣称为医学审核、实际操作认证或学习效果验证。
