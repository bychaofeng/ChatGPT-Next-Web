# 运动康复学习 APP：训练任务协议 v0.1

版本日期：2026-09-26  
性质：产品与技术设计草案；不是已经实现的 APP、医学题库或经过验证的能力评定标准。

## 0. 这版先解决什么

为安卓端的一个训练单元约定：出什么、用户能做什么、怎样保存作答、如何评价、什么可以进入能力画像、什么时候结束。暂按单人使用、本地档案、自带模型 API Key、模拟教学病例设计。真实病例辅助讨论不在本协议的执行范围内；它以后只能向训练模块提供去标识化的“待验证能力线索”，不能直接改写能力评价。

第一条原则：一次训练完成，不等于某项能力已掌握。

第二条原则：训练单元不是一句问题，而是一个明确目标、一个固定情境、若干允许的行动、可核对的评分依据，以及本次表现的证据。

第三条原则：下列教育阈值、复测间隔和调度规则均为产品试用设定，不是临床能力认证，也不是已验证的心理测量模型。

## 1. 先固定的设计决定

1. 原始作答、评价意见、能力画像分开。原始作答提交后冻结；改答案形成新记录，不能覆盖首次答案。正常修订用新版本；用户依法和依产品政策删除个人数据时是另一条流程，不能以审计为理由永久保留原文。
2. 提示、答案展示、看过相似题和允许使用的工具都影响证据解释；请求病例中的客观信息不自动算提示。
3. 训练模式明确告知目标并允许教学；独立复测模式只给中性题名和完成任务所必需的信息，不能在标题、推荐理由里提前泄漏评分关键点。复测不是隐藏式考试，用户始终知道当前模式。
4. 病例事实、题目版本、评分规则在展示前固定。未知就写未知；不能在对话中临时添加决定答案的新事实。
5. 评价只能针对用户当时可知的信息和题目要求。病例问答中的信息收集行动也属于可评价的表现，不能只看最终一句答案。
6. AI输出是候选意见。程序校验结构、引用、权限和流程；专业内容仍须内容审核与质量监测，结构校验不证明医学正确。
7. 每个能力点按具体场景保存证据，不生成脱离情境的“康复总水平”。不能把模拟推理通过等同于现场操作合格。
8. 自动生成的题默认是练习题。进入稳定能力评估的题必须满足单独的内容准入要求；动态不等于每一条内容都可以自动成为评估标准。
9. 一次作答针对一个评分要点，同一时间最多存在一份生效评价；重试不增加练习样本。不同措辞、姓名或年龄不当然构成新的题目家族。
10. 模型没有任意数据库写权限；不能创建真实复测证据、直接提高用户等级或修改病例事实。

## 2. 逻辑记录：它们可以放在同一个本地数据库

这不是要求建设多个服务。下面各记录分别承担职责，第一版可全部在一个安卓工程中实现。

### 2.1 SkillDefinition：能力定义

必需字段：`skill_id`、`version`、`label`、`scope`、`observable_behaviors`、`prerequisite_skill_ids`、`rubric_criterion_ids`。

`scope`包括专业主题、模拟任务类型及工作范围。`observable_behaviors`写行为，而非“理解很好”等空泛形容。例如：“信息不足时指出需要补充的执行与结果信息，并说明其用途”。

### 2.2 TaskSpec：任务意图

必需字段：`task_spec_id`、`policy_version`、`primary_skill_id`、`secondary_skill_ids`、`mode`、`internal_goal`、`selection_reason_code`、`selection_evidence_ids`、`difficulty_axes`、`resource_policy`、`completion_rule`。

- `mode`：`learning` / `independent_probe`。即时巩固与延迟复测另用 `probe_kind` 标记，不混同。
- 第一版每题一个主能力点；旁支能力只有在题目有明确评分机会时才记录。
- `difficulty_axes`分别记信息完整度、提示程度、干扰信息、目标冲突和情境约束，不用一个未经校准的难度总分代替。
- `resource_policy`说明能否查给定资料。查资料本身是任务要求时，不应当作作弊；应用内“独立”仅表示在已记录条件下未提供教学帮助，不是监考认证。
- 选择理由在复测前只显示中性版本，完整原因可在结束后展示。

### 2.3 TaskSnapshot：实际呈现的固定题目

必需字段：`task_id`、`task_version`、`template_id`、`item_family_id`、`task_spec_id`、`public_prompt`、`case_facts`、`reveal_rules`、`rubric`、`reference_snippets`、`quality_gate`、`created_at`、`content_hash`。

- `item_family_id`由受控模板与出题规则确定。只是改写文字仍属于同一家族。自由生成且无法确认家族关系时，标记不明，不把它算成独立的迁移证据。
- `case_facts`中每项都有 `fact_id`、内容和可见条件；明确区分开场提供、询问后可提供、尚未取得的信息。
- 评分要点保存 `criterion_id`、适用技能、要求、可接受的不同路径、不能据此评判的情况、重要安全边界及依据。不能只有一个标准答案句子。
- `reference_snippets`保存来源定位、版本/日期、片段标识和审核状态。模型只能引用传入的标识；不能自行创造一个看似存在的来源。
- `quality_gate`：`draft` / `practice_only` / `probe_eligible` / `withdrawn`。其中 `probe_eligible` 是本产品的内容准入标记，不代表官方认证或绝对正确。
- 对知识解释或评分逻辑有实质影响的变式，要重新核查。仅通过 JSON 或一致性检查不足以获得 `probe_eligible`。
- 图片/3D可预留 `anatomy_structure_ids`，但不影响主流程。高亮结构不是病例病因判断。

### 2.4 TaskRun：用户这一次进入任务

必需字段：`run_id`、`learner_id`、`task_id`、`task_version`、`root_learning_episode_id`、`parent_run_id`、`phase`、`lifecycle`、`state_revision`、`visible_fact_ids`、`exposure_state`、`started_at`、`closed_at`、`close_reason`。

- 一次即时变式使用新的题目/Run，但保留相同 `root_learning_episode_id`，防止把一轮讲解后的重复成功伪装成多个独立证据。
- 复测使用新的Run和学习事件编号；仍保留题目家族与此前相关教学暴露的关系。
- 任务暂停时保存原阶段，不新建一轮，不重新出题。

### 2.5 InteractionEvent：发生过的动作

必需字段：`event_id`、`run_id`、`sequence_no`、`event_type`、`occurred_at`、`related_attempt_id`、`revealed_fact_ids`、`instructional_help_type`、`affected_skill_ids`、`payload_ref`。

`event_type`包括请求病例信息、接收病例信息、澄清措辞、请求提示、提示已展示、解释已展示、提交答案、暂停、继续、提出争议、退出。

发送请求但尚未展示提示，与提示已经展示不同。应用以实际展示和已知暴露记录为准；无法确认是否形成提示时，把独立性记为不确定，不直接记作错误。

### 2.6 Attempt：一次提交

必需字段：`attempt_id`、`run_id`、`task_version`、`submission_no`、`answer_text`、`answer_hash`、`action_event_ids`、`visible_fact_ids_at_submit`、`help_event_ids_at_submit`、`resource_use`、`user_certainty`、`submitted_at`。

- 先在本地保存不可变提交，再调用模型。编辑草稿不产生正式评价；修改已交答案要新建Attempt。
- 允许“不知道”、请求教学、合理地说明信息不足。未作答、接口失败、暂停不等同于不会。
- `user_certainty`可选，例：确定/拿不准/猜测。它是用户自报信息，不是能力分。
- 不强制长篇自述，不储存模型的隐含推理链；只保存可核对的评分依据和简短解释。

### 2.7 EvaluationRevision：候选评价及修订

必需字段：`evaluation_id`、`revision`、`attempt_id`、`input_snapshot_hash`、`rubric_version`、`model_provider`、`model_name`、`prompt_version`、`criterion_results`、`validation_results`、`status`、`supersedes_evaluation_id`。

每个 `criterion_result` 包括：`criterion_id`、`outcome`、`answer_quotes`或`action_event_ids`、`brief_basis`、`ambiguity_codes`、`proposed_safety_issue`。

- `outcome`：`met` / `partly_met` / `not_met` / `not_assessed` / `uncertain`。
- `not_met`需要任务确实要求、信息条件允许判断；题目未覆盖应为 `not_assessed`，答案含混可为 `uncertain`。
- 引文必须存在于本次提交中；不能引用其他用户、其他病例或后来的答案。
- `status`：`candidate` / `accepted` / `disputed` / `rejected` / `superseded`。
- 模型自报“很有信心”不能成为自动通过校验的理由。
- 评价器不读取“用户总体很强/很弱”的印象标签。它读取当前任务、评分要求、可见信息、合法行动与已记录帮助。

### 2.8 EvidenceRecord：对能力画像有意义的证据

必需字段：`evidence_id`、`learner_id`、`skill_id`、`scope`、`attempt_id`、`criterion_id`、`active_evaluation_id`、`observation_type`、`assessment_eligibility`、`exclusion_reasons`、`item_family_id`、`root_learning_episode_id`、`occurred_at`、`policy_version`。

证据分开记录：待验证线索、提示后表现、即时巩固表现、符合条件的独立作答、间隔复测表现。成功与失败都按同一套准入条件处理，不能只收藏成功。

### 2.9 SkillProjection 与 ReviewPlan：能力摘要和下一步

`SkillProjection`必需字段：`learner_id`、`skill_id`、`scope`、`policy_version`、`evidence_ids`、`independent_result_counts`、`guided_result_counts`、`distinct_item_families`、`retention_observations`、`unresolved_conflicts`、`last_observed_at`、`freshness`、`needs_verification`。

`ReviewPlan`必需字段：`plan_id`、`skill_id`、`reason_code`、`target_mode`、`not_before`、`target_date`、`status`、`source_evidence_ids`、`policy_version`。

画像是可重建结果，不是原始记录。到期未练只改变“需要复测/证据不新鲜”，不自动宣布能力下降。

## 3. 流程：教学阶段、运行状态、评价状态分开

### 3.1 主阶段

| 阶段 | 允许发生的事 | 离开条件 |
|---|---|---|
| PREPARING | 选择已有题或生成、核查、固定快照 | 任务具备当前模式的内容资格 |
| ANSWERING | 读题、请求病例信息、记录草稿、提交、选择提示 | 答案本地提交成功，或用户明确转教学 |
| EVALUATING | 调用评价器、校验结构与依据 | 合格评价进入反馈；失败仍待评价；不伪造分数 |
| FEEDBACK | 展示逐项评价、说明依据、接受申诉 | 进入教学、安排新变式或总结 |
| TEACHING | 提示、解析、图示、追问、用户解释 | 用户可以直接结束，也可自愿做即时巩固 |
| SUMMARY | 说明练了什么、实际表现、证据限制、复测建议 | 正常关闭任务 |

`lifecycle`独立保存 `active` / `paused` / `closed`。`close_reason`为 `completed` / `user_exit` / `content_invalid`。评价状态在 EvaluationRevision 中单独保存。

### 3.2 转移约束

- 未校验题目不能进入复测；未保存答案不能发起其评价请求。
- 用户在评价中请求提示，原提交继续依据提交前快照评价；提示后的新答案不能覆盖它。
- 用户暂停时保留原阶段。已发出的请求可尝试取消，但不能保证供应商不计费；晚到结果仅在输入版本匹配时保存，不能自动跳走用户当前页面。
- 从独立复测切到教学允许且要明确显示；同一道题看完讲解后不能切回“全新独立复测”。
- 每轮默认处理一个主要缺口。默认至多一次可选的即时巩固；继续深入由用户主动选择，不让模型无限延长本轮。
- 内容被确认无效时停用题目，关闭受影响任务；撤销相关评价影响，不记录成用户失败。

## 4. 什么算提示，什么不算

| 行为 | 默认解释 | 对独立证据的影响 |
|---|---|---|
| 用户询问事先设定的病例事实 | 任务内的信息获取行动 | 不自动降为提示；可成为能力证据 |
| 界面辅助或不引入考点的措辞解释 | 可访问性/中性澄清 | 保留独立性；若意外揭示考点则另记 |
| 系统指出应考虑哪一类问题 | 教学方向提示 | 影响之后的相关作答，标记提示后完成 |
| 展示评分关键点、答案或解析 | 答案暴露 | 本题此后不再形成全新独立证据 |
| 刚讲完后换个相近案例 | 即时巩固 | 可记学习进展，不当作保持能力证明 |
| 在规定条件下进行新的间隔复测 | 可能的保持证据 | 通过全部准入条件后才记录 |

第一版可采用保守策略：一次明确的目标相关提示，标记本题后续答案为有帮助；不追求自动精确分配到每个词。实际支持更精细帮助归因时再扩展。不能把看不懂题干一律归为专业能力不足。

## 5. 画像更新协议

### 5.1 先决定是否可用，再评价表现，不直接加总分

符合条件的独立证据须同时满足：

- 内容为 `probe_eligible`，且未撤回；目标技能与评分要点均存在且版本匹配。
- 评价已接受、无未解决的实质争议；引文和行动引用可核对，输入快照匹配。
- 是题目要求范围内的表现，信息足以作相应评价。
- 无影响本次提交的提示/答案泄漏；资源使用符合任务规定，无法确认时如实标注。
- 未被当作同一次任务的重复评价计算；题目暴露、家族和同一教学事件关系已经记录。

这些是可靠记录的门槛，不是专业正确性的数学证明。对重要安全疑点和内容争议，先提示核查并暂停相关结论；不能把另一个模型重复同意当作独立权威验证。

### 5.2 第一版不设置“掌握80%就升级”

优先显示可解释事实：某类模拟题中的独立完成次数及分母、提示后表现、覆盖了多少受控题目家族、是否有新情境与间隔复测、是否有矛盾结果。

展示例：

> 这一能力已有2个题目家族的独立作答记录；3次中2次达到评分要点。尚无间隔复测。最近一次在信息不足时过早调整方案，建议下一次练习核查依据。

这里的数字只能来自真实记录，不能由模型补写。

可以使用描述性状态：“尚未评估”“主要在帮助下完成”“已有独立完成记录”“已有间隔复测记录”“需要再次核实”。它们描述证据，不是临床资质等级，也不应被实现为只升不降的单一阶梯。

### 5.3 每次事件如何影响画像

- 聊天中的一句“懂了”：记学习活动，不增加独立成功次数。
- 提示后答对：记有帮助的进展，不擦除首次独立作答中的问题。
- 合格独立题完成或未完成：记相应表现；一次失误不把全部能力清零。
- 即时相近变式答对：记即时巩固，不记长期保持。
- 符合条件的新题复测：记复测时间、情境和表现；不自动扩展到所有身体部位或现场操作。
- 出现新矛盾证据：保留正反两方面，标记需要核实，调度新验证题。
- 用户申诉：冻结该项评价对画像的生效影响，核查后恢复或修订。申诉本身不算用户答对。
- 题目撤回：使相关证据失效并重建画像。保留必要修订说明，按个人数据删除规则处理原始内容。

### 5.4 调度的初版默认

优先处理未解决的重要安全/内容问题，但安全提示不等待完成测验。争议题送核查，不拿争议成绩强化“薄弱”。然后在到期复测、需要补充的已观察缺口、未覆盖能力和用户主动目标间选择。

同一能力连续练习不得无限占用会话；允许用户改主题、结束和改约复测。初次独立复测可试用约3天后的目标日期，之后根据表现再安排约7天或更久；这些只是可配置的试用日程，不称作已验证的记忆曲线。用户修改日期不算失败。

间隔记录从最近一次与该技能相关的已知教学/答案暴露计算，而不只是上一次正式测试；同时承认应用不知道用户在外部获得的所有帮助。未获得独立样本前，不宣传其实际临床进步。

## 6. 三种模型任务，与程序的权限边界

### 6.1 生成器

输入：TaskSpec、审核过的模板/参考资料、允许变化的条件。
输出：TaskSnapshot候选，含事实、公开题面、评分要点、来源引用。
权限：不能自行创建已审核来源、获得复测资格或写用户画像。自由生成默认 `practice_only`；结构不完整不得展示为正式题。

### 6.2 教学助手

输入：当前任务、当前已开放事实、用户相关的教学需求摘要、近期相关对话、已发生提示。
输出：一次说明或追问，以及是否发生目标相关提示的记录建议。
权限：阶段内病例回答只能依据允许披露的事实；提前透露的答案必须被记为暴露。没有任意数据库写权限，不可读取其他病例或完整个人档案。

### 6.3 评价器

输入：不可变作答、题目、相应评分要点、作答前可见信息、任务内行动和提示/资源记录。
输出：逐项候选评价、证据引用、简短依据和无法判断的原因。
权限：不看整体印象分，不读取本次提交后的用户改答，不直接更新长期画像。允许合理替代路径；看不清时请求中性澄清或标记不确定。

这三种任务可以由同一服务商或同一模型实现，不需要三个互相对话的智能体。无须每题调用全部三种：已有题不调用生成器，未请求深入解释时不额外启动长对话。

DeepSeek的聊天补全接口不负责保管跨请求的对话上下文，应用须自行提供本次必要内容[1]。JSON Output仍有空输出和截断处理要求[2]。程序必须拒绝无效结构、未知ID、伪造引文、越权动作及过期请求，不直接执行模型返回的操作；输入、输出、记忆与权限的隔离可参照OWASP建议[3]。

## 7. 数据一致性与失败处理

1. 本地保存Attempt和待处理请求记录；网络请求在数据库事务之外执行。
2. 请求附带 `request_id`、`attempt_id`、`answer_hash`、`task_version`、`rubric_version`、`input_snapshot_hash` 和预期状态版本。
3. 返回后先校验结构、引用及当前有效版本。只有匹配的结果才能作为候选评价；过期结果不覆盖新提交。
4. 接受评价、替换生效证据、重建受影响能力摘要、更新复测计划，放在同一个本地事务中。Room提供事务接口[4]；具体幂等与唯一约束仍由应用实现。
5. 同一 `learner_id + attempt_id + criterion_id`最多有一份生效评价。修订不是再加一次分，而是替换有效版本后重建。
6. 超时、空输出和断网记“待评价/评价失败”，不是答错。限制重试次数；预算不够时保留当前内容，不无限自动重试。
7. 本地档案、已缓存题目和草稿可离线读取；新生成和开放式评价明确需要网络。Android官方离线优先架构以本地持久数据为界面读取依据[5]。
8. API Key不进入模型上下文、答题导出或日志。调试默认保留请求元数据和版本，不默认收集全量私密原文。重试去重只保证本地不重复记分，不保证服务商不会对重复请求计费。
9. 模型、提示词、参考资料或评分政策变化要保留版本。原始表现可重放核查，但新旧分数不默认等价；不能伪造历史进步曲线。

## 8. 一条示例路径

以下为虚构设计说明，不是具体治疗建议。

任务：用户面对“练了一段时间但感觉没有改善”的复评描述，需要说明决定是否调整前还应核实什么。

- 首次作答：“原来练习不适合，先换掉。”在题目实际要求下，评价认为尚未体现对执行与结果依据的核查。保存原话和当时条件。
- 系统提供方向提示：“目前是否知道计划实际完成了多少、按什么指标判断改善？”标记提示已展示。
- 用户再次作答，提出核实实际执行、目标观察和变化情况。记录提示后完成，不覆盖首次答案。
- 用户接受简短讲解并退出：本轮可以完成，画像仍显示该能力需要独立验证。
- 同一天可选新变式：表现只记即时巩固。
- 后续按试用日程安排新题。使用符合复测资格的内容、中性标题、未展示解析和已记录资源条件；再记录真实独立表现。

附带JSON是上述部分过程的数据形状示例。它明确标记 `design_fixture_only`，内容未经过医学审核，不能作为已审核题库导入生产环境，也不证明任何人的水平。

## 9. 第一条可开发的完整路径

仅实现一个主要能力点、一份固定且审核流程明确的题目、一次独立提交、一次提示后再答、逐项反馈、本地证据与摘要、暂停恢复和待复测记录。动态生成先作为练习扩展，而不是拿未校准的生成题直接产生等级。

开发顺序：

1. 完成记录结构与约束，用固定虚构输入检验存取和重建。
2. 完成固定题的交互与状态转移，先用固定评价响应测试断网、重试、暂停。
3. 接入模型评价和教学，核对相同输入下的评分偏差及合理替代答案。
4. 加入生成器与任务调度，并继续保持内容准入和重复题关系记录。

## 10. 必须验收的情况

| 场景 | 应有结果 |
|---|---|
| 用户主动追问病例的既有事实 | 当作任务内信息获取，不自动算提示 |
| 题名或提示意外说出评分关键点 | 记录暴露，受影响提交不算全新独立证据 |
| 首次答错、看解析后答对 | 同时保留首次表现与提示后进展，不互相覆盖 |
| 表达不同但理由合理 | 允许匹配同一评分要点，不强迫复述标准句 |
| 病例未提供某信息 | 返回未知，不能临时编造，也不能据隐藏事实扣分 |
| 用户说不知道或中途退出 | 分别记录求助/退出，不伪造成安全错误 |
| 请求超时后重试两次 | 本地最多一份生效评价；所有费用情况如实记录 |
| 用户改答后旧请求才返回 | 不能覆盖新Attempt；仅与旧提交关联，按版本核验 |
| APP被关闭后恢复 | 恢复原题、事实可见范围和提示状态，不重新抽题 |
| 用户申诉且结论待核查 | 冻结该项影响，不自动判用户正确或错误 |
| 题目被撤回 | 对应证据失效，画像和复测计划可重建 |
| 只换名字或改写句子 | 不自动增加题目家族覆盖数 |
| 模型要求忽略规则并改画像 | 无该写权限，输出被拒绝，原始记录保持 |
| 长时间未登录 | 标记需要复测，不自动生成失败或推断能力下降 |
| 用户删除数据 | 删除相关原文及其派生画像，遵守备份和导出保留说明 |

以上为验收要求，不意味着APP已经实现或所有测试已经执行。附带结构示例仅验证数据格式与部分设计一致性，不验证医学正确性或教学效果。

## 11. 试用中必须收集的证据

查看评分争议、无效题、提示误分类、重复题泄漏、独立复测表现与实际调用成本。把“用户觉得顺畅”“完成了更多训练”和“独立模拟表现有所改善”分开分析。没有现场测评时，不从文字任务结果宣称真实操作能力提升。

第一版不设置排行榜、不可解释的总分、根据写作长度加分或按答题速度判断专业水平。应通过独立于日常练习的审核案例检验迁移；改变评分模型时使用固定样例回归检查，记录不确定与失败，不把模型同意率当作医学真值。
