# 产品总方案：自适应运动康复学习工具

整理日期：2026-10-02。来源：本项目需求讨论及已存设计文档。以下是产品设计目标，不是医学效果结论或全部已实现功能。

## 1. 要解决的问题

用户不是为了刷更多题而刷题，而是希望面对没见过的康复学习情境时，更会收集信息、解释依据、选择行动、观察反馈和调整计划。

产品应完成：发现可能缺口 → 独立尝试 → 辨别错因 → 针对性讲解 → 变式尝试 → 间隔复测 → 按新证据调整后续训练。

不以“AI生成了多少题”“聊了多久”代替学习结果，也不以文字作答认证触诊、手法、现场保护或实际治疗能力。

## 2. 通用系统，自动个性化

所有用户共用能力定义、内容准入、评分和调度规则；各自拥有独立的作答、帮助记录、学习线索和画像。朋友可以是首位试用者，但不是程序中写死的默认用户。

用户首次进入可以直接开始。没有资料时标记未知，不默认初学者，也不要求填写学历、资历或自评分。用户仍可主动选主题、换难度体验、求助和结束；这些偏好不是能力证明。

初次任务只帮助寻找起点，不以少量回答给整个人定级。不同能力可处在不同阶段；换到未覆盖的专业情境时，重新补充观察，不自动把局部表现推广到全身或所有工作场景。

## 3. 两个入口，一套学习记录

### 3.1 日常训练（当前原型的主线）

系统建议本轮目标，用户完成短题或连续病例任务。解析后可继续讨论，退出时说明本次表现和仍需验证的部分。下一次根据有效记录安排探索、补练或复测。

### 3.2 病例讨论（分阶段扩展）

第一步保留围绕当前模拟题的教学讨论。后续再增加独立的模拟病例讨论入口，整理事实、未知信息、不同解释和后续观察。

讨论中出现的疑点先形成待验证线索，进入后续训练，而不是聊天结束就直接增减能力。真实病例辅助讨论需单独设计授权、去标识化、风险边界、发送预览及保存政策；当前原型没有该入口。

知识资料、学习者画像和单个病例事实逻辑隔离。画像只调整教学深浅，不改变事实和安全边界，不把一个病例的假设带进另一个病例。

## 4. 训练哪些能力

以下八项是本产品的工作拆分，不是官方能力等级。解剖、运动学等基础知识作为相应行为的支撑；遇到缺口时可回补，而不是要求所有用户先背完一套教材。

| 能力 | 要观察的行为 | 适合的任务 |
|---|---|---|
| 目标与优先级 | 知道对方要恢复什么，能说明先处理什么 | 从背景中提出目标及优先顺序 |
| 获取与理解信息 | 找出影响判断的缺失信息，不把观察直接当成原因 | 下一步问什么、某信息能说明什么 |
| 比较解释与不确定性 | 比较支持和反对依据，知道何时不能下结论 | 提出备选解释、指出改变判断的条件 |
| 可执行的计划 | 把目标、内容、安排、现实条件联系起来 | 说明选择理由、执行方法和观察条件 |
| 复评与调整 | 根据实际执行和结果决定保持、调整或重新评估 | 原计划效果不理想时怎样处理 |
| 沟通与共同决策 | 解释清楚、发现执行障碍，尊重选择 | 面对疑虑或不同偏好进行沟通 |
| 安全与工作边界 | 识别需要暂停、核查或寻求其他帮助的情况 | 判断当前信息和能力范围是否足够 |
| 依据核查与反思 | 核对外部建议，包括 AI 建议，承认未知并纠错 | 比较资料条件、检查建议的证据与限制 |

具体医学内容、剂量、风险信息和评分依据须经过对应内容审核。这里定义的是训练行为，不提供患者治疗方案。

## 5. 从哪里开始，到哪里结束

每项能力可经历：看懂示范 → 提示下完成关键一步 → 独立处理常见情境 → 新信息出现后修正 → 在不同情境和间隔后仍能运用。

这些不是必须逐级解锁的全局等级。已有充分表现的部分不强制重学；不确定的地方安排澄清或新任务，不能直接断定不会。

一次训练在本轮目标得到处理、完成反馈或用户选择结束时可以结束。一次训练结束不等于稳定掌握。

一个能力单元转入维护复习，需要新的合格题目、合适的独立条件和延迟观察。长期未使用只提示需要复测，不自动判定退步。整条学习方向允许阶段性完成，不为延长使用而无限增加罕见情节。

## 6. 怎样出题与加难

先确定本次主要目标、选择原因、评价机会和允许的帮助，再选择题型或生成题面。一题主要练一个行为，旁支没有明确评价机会就不计分。

建议题型：下一步决策、比较两种解释、只改变一个条件、检查 AI 建议、用自己的话解释、收到随访信息后修正。选择题负责轻量练习，开放题负责依据表达，病例推演负责连续判断。

难度可来自提示减少、信息不齐、干扰信息、执行限制、目标取舍和证据变化。先增加一种主要难度，再组合。不是病名越稀奇越好，不默认所有题都有隐藏病因或剧情反转。

病例事实、已知与未知、开放条件和评分依据在展示前固定。用户主动询问允许的事实是信息收集表现，不自动算提示；系统指出思考方向、展示答案或解析才属于教学帮助。评分只用提交时可获得的信息。

动态生成的题默认用于练习。形成较稳定能力判断的内容需要单独准入；题干改写不自动成为新题目家族。缺少可靠题目时应说明无法完成某种验证，而不是假造掌握状态。

## 7. 解析与互动体验

解析先说本题关键与作答证据，再按需展开原理、反例和来源。用户可以直接指出不懂的地方，不必重新描述整道题。必要时用一个小追问区分知识缺口、漏看信息、解释含混或过早判断。

不按篇幅、文风或自信语气判断专业水平。合理不同路径可以被接受，信息不足也可以是好答案。用户质疑评分时提供核查入口；求助如实记录，但不作为羞辱或惩罚。

每轮默认处理一个主要缺口，至多主动提供一次可选即时巩固；继续深聊由用户选择。等待、失败、暂停、重试和恢复都属于正常体验设计，不把接口故障算成用户答错。

## 8. 解剖图与 3D

先验证用户卡在空间理解还是推理依据。前者可用核对过的二维局部图，后者可能更适合证据对照。后续用稳定的结构编号关联题目、资料和有清楚授权的 3D 资源。

AI选择展示内容，不临时生成一套未经核对的解剖事实。高亮结构只表示正在解释，不表示已经确定为病因。完整 3D、语音与图像评估不作为当前训练流程成立的前提。

## 9. 怎样判断产品值得继续

分别观察可用性、评价可靠性和学习表现，不混为一个满意度数字。

可用性看能否顺利开始、理解反馈、合理结束和恢复；可靠性看无效题、错误引用、评分争议和帮助误分类；学习表现看没见过的合格题、不同情境和间隔后的独立完成情况。

固定题目与评价案例用于版本回归，独立留出的案例用于后续学习效果验证。工程测试通过不代表专业正确；目前没有经验证的学习效果结论。
